Cómo trabajo

Correcciones pequeñas, razones claras.

Los mantenedores tienen poco tiempo. Cada cambio que envío es fácil de revisar y fácil de confiar.

Primero, un test que falla

Cada pull request empieza con un test que reproduce el bug, así la corrección queda demostrada, no supuesta.

La causa raíz, explicada

Cada PR dice qué se rompió, por qué se rompió y por qué esta es la corrección correcta.

Diffs pequeños y enfocados

Un problema por pull request, con el estilo del proyecto, para que los mantenedores puedan aceptarlo rápido.

Raiko.js

Framework TypeScript full stack

Backend y frontend en un solo árbol de archivos: un app router al estilo de Next.js con server components, una API y un cliente tipados, WebSockets con cifrado AES-GCM en Bun, Node, Deno y Cloudflare Workers, autenticación con OAuth y 2FA, un panel de administración con permisos por acción y plantillas de email en TSX. Las páginas renderizan 24x más rápido que Next.js 15 en el mismo Node. npx create-raiko@latest configura el frontend, el CSS, la base de datos, el inicio de sesión y el destino del deploy.
