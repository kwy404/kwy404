仕事の進め方

小さな修正と、明確な理由。

メンテナーは忙しいものです。送る変更はすべて、レビューしやすく信頼しやすい形にしています。

まず失敗するテストから

すべてのプルリクエストはバグを再現するテストから始めます。修正は推測ではなく、証明されたものです。

根本原因を説明

各 PR で、何が壊れたのか、なぜ壊れたのか、なぜこの修正が正しいのかを説明します。

小さく焦点を絞った差分

1 つのプルリクエストで 1 つの問題を、プロジェクトのスタイルに合わせて扱います。メンテナーがすぐにマージできます。

Raiko.js

フルスタック TypeScript フレームワーク

バックエンドとフロントエンドを 1 つのファイルツリーで扱えます。サーバーコンポーネント対応の Next.js 風 app router、型付きの API とクライアント、Bun、Node、Deno、Cloudflare Workers で動く AES-GCM 暗号化 WebSocket、OAuth と 2FA による認証、アクションごとの権限を持つ管理画面、TSX のメールテンプレートを備えています。同じ Node 上で Next.js 15 より 24x 速くページをレンダリングします。npx create-raiko@latest でフロントエンド、CSS、データベース、サインイン、デプロイ先をセットアップできます。
